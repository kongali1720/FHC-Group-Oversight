# Contributing Guidelines

Thank you for helping improve the FHC Group Oversight & Private Equity Framework.

## Before proposing a change

- Keep documentation clear, accurate, and operationally useful.
- Distinguish proposed processes from approved company policy.
- Do not add confidential company, investor, employee, customer, banking, or transaction information.
- Do not include credentials, API keys, private keys, access tokens, or unredacted identity documents.
- Do not present legal, tax, accounting, investment, or regulatory conclusions as confirmed without appropriate review.

## Suggested workflow

1. Create a branch for your change.
2. Make focused edits and use descriptive file names.
3. Check Markdown formatting and Mermaid diagram syntax.
4. Review links and ensure no confidential data is present.
5. Open a pull request describing the purpose, scope, and impact of the change.
6. Obtain review from the appropriate document owner before treating changes as approved policy.

## Commit message examples

- `docs: clarify investment approval workflow`
- `docs: add monthly finance reporting template`
- `fix: correct organization diagram`
- `chore: update repository standards`

## Approval status

A change merged into GitHub is not automatically a formally approved corporate policy. Formal approval must be recorded through the company's designated governance process.
